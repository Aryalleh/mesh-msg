# LoRa node firmware

Design: [docs/firmware.md](../docs/firmware.md). This tree is being built bottom-up:
board-independent libraries first, tested on the host, then the radio/board layer.

```
lib/meshproto/src/   pure C++17, no heap, no Arduino (runs on boards and on the host)
  packet             outer header codec, hop increment, fragmentation/reassembly,
                     LoRa link frames (sender short ID || packet), e2e prologue
  sha256             destination hashes and receipt IDs
  identity           X25519/Ed25519 keys from a seed, destination hash, domain signatures
  announce           verify/build ANNOUNCE and RECEIPT packets
lib/meshroute/src/   LoRa managed-flood router: seen-cache (packet ID + fragment, 24 h),
                     SNR-ordered rebroadcast delay, cancel after hearing N copies, hop
                     limit / NO_LORA, implicit-ACK retries for own packets, public keys
                     learned from announces so verified receipts purge queued copies
lib/monocypher/      Monocypher 4.0.2 (X25519, Ed25519), vendored unmodified, CC0/BSD-2
test/                host tests: spec/test-vectors conformance, edge cases, random-input
                     round-trip fuzz, router behaviour + router fuzz
```

## Tests

```
make test      # needs a C/C++ compiler; builds with ASan + UBSan
```

The tests load `../spec/test-vectors/vectors.json` (generated by the Go core with
`go run ./spec/cmd/genvectors`) and require byte-identical output for headers, hop
increments, fragment sets, link frames, identities, announces and receipts, including
rebuilding signed packets from their seeds. The compact-text vectors are end-to-end payload
that nodes never see, so the firmware does not implement them.
