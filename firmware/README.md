# Mava board firmware

Firmware for the Mava custom board (ESP32-S3-N16R8 + SX1262), the only supported LoRa
device: [docs/board.md](../docs/board.md). Design of the node: [docs/firmware.md](../docs/firmware.md).
Board-independent libraries, tested on the host, then a thin board layer.

```
lib/meshproto/src/   pure C++17, no heap, no Arduino (runs on boards and on the host)
  packet             outer header codec, hop increment, fragmentation/reassembly,
                     LoRa link frames (sender short ID || packet), e2e prologue
  sha256             destination hashes and receipt IDs
  identity           X25519/Ed25519 keys from a seed, destination hash, domain signatures
  announce           verify/build ANNOUNCE and RECEIPT packets
lib/meshroute/src/   LoRa managed-flood router: seen-cache (packet ID + fragment, 24 h),
                     SNR-ordered rebroadcast delay, cancel after hearing N copies, hop
                     limit / NO_LORA, implicit-ACK retries for own packets, public keys
                     learned from announces so verified receipts purge queued copies
  mac                exact LoRa time on air, sliding-hour duty-cycle budget (1-minute
                     buckets, announce share cap), priority queue, CAD + exponential backoff
  store              bounded packet store: per-sink backlog (phone / uplink, receipts
                     first), value-ordered eviction, per-destination quota, fixed-size
                     records for a flash backend + restore after reboot
lib/meshnode/src/    the node application, still pure and host-tested
  hostlink           phone/PC byte stream (COBS frames + CRC, commands/events, config
                     TLVs, status block, region frequency plans, presets)
  node               wires router + MAC + store to a radio, two host ports at once (USB,
                     BLE) and the internet uplink: every packet in on one side goes out on
                     all the others; config, own announces once the time is known
lib/meshtastic/src/  the Meshtastic backbone: Mava packets as PRIVATE_APP payloads in
                     Meshtastic radio frames (channel AES-CTR, hash), relays under the
                     original sender/id so Meshtastic nodes do not flood twice
lib/meshkeys/src/    handheld keyboards (7 × 7 matrix, BlackBerry 9900, 9900 + trackpad):
                     debounce, Persian (ISIRI 9147) / Latin layers, Alt + Shift, Sym, and
                     kbproto: the keyboard module's I2C protocol
keyboard/            keyboard module firmware (RP2040, Arduino-Pico): scans the keyboard
                     and the 9900 trackpad, I2C target 0x1F for the ESP32-S3
lib/monocypher/      Monocypher 4.0.2 (X25519, Ed25519), vendored unmodified, CC0/BSD-2
src/                 the board layer (Arduino / PlatformIO), nothing that decides anything:
  main                boots the node from flash (identity, config, stored packets) and runs
                      the loop: Meshtastic radio, USB host (port 0), BLE host (port 1),
                      Wi-Fi, timer; logs what is heard until a USB host attaches
  radio               SX1262 through RadioLib: Meshtastic LongFast, TX, RX, CAD, retune
  ble                 NimBLE GATT host link (docs/firmware.md §6), passkey pairing
  net                 setup switch, hotspot + captive-portal panel, Wi-Fi, NTP, relay worker
                      (POST /v1/gateway with proof of work: upload + long-poll)
  board               hardware RNG, LittleFS files, chip selects, setup switch, reboot
  kbmodule            the keyboard module on I2C: key positions → text and actions
  ui/                 LVGL UI: display (ILI9341 + XPT2046 touch), screens, touch keyboard,
                      Messenger interface (stub: local notes), Vazirmatn font
lib/meshui/src/      touch keyboard layouts (Persian, Latin, symbols), host-tested
sim/ui/              the UI on the host: `make uishots` renders every screen to PPM
sim/                 meshnode-sim: real nodes on a simulated radio, one pty per node
test/                host tests: spec/test-vectors conformance, edge cases, random-input
                     round-trip fuzz, router behaviour + router fuzz, MAC, and a multi-node
                     radio network (real Router + Mac, half-duplex, collisions, CAD), store,
                     host link, and whole nodes over a simulated radio with fake hosts
```

## Tests

```
make test      # needs a C/C++ compiler; builds with ASan + UBSan
```

The tests load `../spec/test-vectors/vectors.json` (generated by the Go core with
`go run ./spec/cmd/genvectors`) and require byte-identical output for headers, hop
increments, fragment sets, link frames, identities, announces and receipts, including
rebuilding signed packets from their seeds. The compact-text vectors are end-to-end payload
that nodes never see, so the firmware does not implement them.

## Board

```
pio run                  # build (env mava_handheld_s3)
pio run -t upload        # flash over USB-C (esptool)
pio device monitor       # log: device password, BLE passkey, packets heard
```

Pins are build flags in `platformio.ini`, wired as the handheld
([docs/handheld-proto.md](../docs/handheld-proto.md)): SX1262 on its own SPI bus (SCK 12,
MOSI 11, MISO 13, CS 10, DIO1 1, BUSY 4, RESET 8), the display, touch and microSD on a second
bus, WM8960 on I2S/I2C, setup switch on GPIO 14, and the **keyboard module** (an RP2040,
`keyboard/`, three envs: `kb_matrix`, `kb_bb9900`, `kb_bb9900tp`) at I2C 0x1F with INT on
GPIO 9. One ESP32 build serves all three handheld versions. **Not yet verified on hardware.**

Files in LittleFS: `/id` identity, `/cfg` node config, `/net` Wi-Fi + relay + channel +
device password, `/cur` relay cursor, `/s00`–`/s63` stored packets. `WIPE` (from a host)
formats the file system, so a new device password is generated on the next boot.
