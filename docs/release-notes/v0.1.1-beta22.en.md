The board's web app gets the board's Wi-Fi settings; sending from the browser is sturdier.

- Web app on the board (http://192.168.4.1/app/): Settings now has "Board Wi-Fi and relay". It shows the board's Wi-Fi, relay and hotspot, lists the networks nearby, and saves the network name and password. The board then joins that network for the relay. Its own hotspot stays on beside it, so the phone stays connected (it may drop for a few seconds). A relay chip at the top shows whether the board reaches the relay.
- The Wi-Fi setting is also still in Mava Flasher (Board Wi-Fi, over the USB cable), and in the setup panel at http://192.168.4.1/ while the hotspot is on.
- "Failed to fetch": the web app now retries a request the board dropped. If the board keeps not answering, the page explains the usual cause: a phone with mobile data on sends the page's requests over mobile data, because the board's Wi-Fi has no internet. Turn mobile data off, or choose "Keep Wi-Fi" when the phone asks.
- Board: more stack for the main loop, where the browser's messages are encrypted.
- Update the board with Mava Flasher: "Install everything" this time (the web app is in it; this gives the board a new identity and the device password 12345678). Still not tested on real hardware.
