Fix: a message sent just before a Bluetooth link broke was never sent again; the board's own messages were pushed out by relay traffic.

- Phones, desktop and the board's partners: when a Bluetooth link to a peer broke, the app still counted everything it had handed to that link as delivered. After the reconnect it sent only new packets, so a message lost in the broken link never arrived. Now a dropped link forgets what it carried, and the reconnect sends it again (the peer ignores what it already has).
- Board: it kept only 64 packets. A phone that passes on its relay traffic, plus the relay itself, brings hundreds a minute, so the board's own message was pushed out before it reached the relay or the phone. The board now keeps 256 packets, and messages written on the board (its screen or web app) are pushed out last.
- Board log: the Bluetooth line says why the last stream was judged corrupt ("last: frame length … after … packets").
- Update both: the Android app, and the board with Mava Flasher, "Update firmware only" (keeps the account). Still not tested on real hardware.
