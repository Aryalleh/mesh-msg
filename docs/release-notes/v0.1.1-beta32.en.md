Voice calls on the Mava board, fixes from the first tests with its display, and Mava Screen as keys, keyboard, speaker and microphone.

- Voice calls on the board: phones call the board and the board calls phones, on the same Wi-Fi or across the internet behind different routers (the same protocol and end-to-end encryption as phone-to-phone calls; Opus, so the phone needs Android 10 or later). In a chat press 📞; an incoming call shows its own screen with Answer and Decline, rings, and shows the code to compare, the path, Mute and Hang up. ⛔ hangs up. Calls need Wi-Fi. Without the audio module, Mava Screen is the board's speaker and microphone: turn both switches on.
- Fixed: the relay connection failing with "SSL - Memory allocation failed". The screen's buffers and TLS no longer compete for internal memory.
- Fixed: "connection refused" with a certificate error after boot. The board now gets the time before its first secure connection (NTP, then the relay's clock), and keeps it with an RTC module if you add one: a DS3231 module on I2C (SDA 47, SCL 48).
- Fixed: touches on the display came out mirrored top to bottom.
- New: navigation keys without a keyboard: nine buttons (Up, Down, Left, Right, OK, Back, Menu, Call, End) on one pin (GPIO 2) as a resistor ladder; wiring in docs/handheld-proto.md.
- Mava Screen, "Show the board's screen here": switch it off when the board has its own display; the phone stays the keys and keyboard. "Board sound on this phone's speaker" and "This phone's microphone to the board" make the phone the board's audio over USB (16 kHz, with the phone's echo canceller). The board has sounds: message chime, key clicks, ring, Settings → Sound test and Echo test.
- Everything the phone simulates (screen, keys, audio) is one firmware library built only into pre-releases; version 1 leaves it out.
- Update the board with Mava Flasher ("Update firmware only" keeps the account) and install the new Mava Screen. Calls on the board are not yet tested on real hardware.
