Board without a LoRa module: a setting that switches the radio off. Fix for a Bluetooth restart storm between phone and board. More in the board log.

- New setting "LoRa module": on the board's screen (Settings) and in Mava Flasher (the "LoRa module" panel, over USB). With "No LoRa module" the board skips the radio: no 10–20 s search for a missing SX1262 at boot (Bluetooth messages waited for it), nothing queued for the air. The log then says "radio off (no LoRa module)".
- Fix (board): when a phone reconnected over a link that was still open, the board could send the tail of the old data after the phone's new greeting (hello). The phone read it as a broken stream, reconnected and greeted again: 27 times a minute in the owner's log, each time resending the whole store. The board now holds its sends on that link until it has handled the greeting.
- Board log: the Bluetooth line counts messages from phones and whom they were for ("messages 2: for 5cf3738e… ×2"). A new "store" line shows what the store holds and how many packets it refused. Together with the "account" line this shows where a message stops.
- Update the board with Mava Flasher ("Update firmware only" keeps the account), and Mava Flasher itself for the LoRa panel. Not yet tested on real hardware.
